# 점검 모드(유지보수) 기능 운영 매뉴얼 — 2026-09-01 정식 운영 전환용

## 개요
- 위치: 관리자 로그인 후 `/admin/maintenance`
- 이 기능은 **서로 다른 두 가지 토글**로 구성되어 있어서 헷갈리기 쉬움 → 이 문서에서 명확히 구분함
  1. **점검 모드**: 즉시 서비스 차단 (진짜 점검 중일 때)
  2. **사전 공지 배너**: 차단은 안 하고 화면 상단에 안내 문구만 노출 (점검 예정 알림용)

---

## 1. 점검 모드 (즉시 차단)

- `/admin/maintenance` 화면에서 입력하는 항목
  - 점검 모드 ON/OFF
  - 점검 안내 메시지
  - 예상 종료 시각
- ON으로 켜는 순간부터 실시간으로 적용됨 (재배포 필요 없음, DB 값만 바뀜)
- 켜져 있는 동안 동작 방식
  - 일반 사용자: 모든 요청이 점검 안내 화면(503)으로 전환됨
  - 관리자(`ROLE_ADMIN`) 세션: 정상적으로 모든 화면 접근 가능 (점검 중에도 설정을 끄거나 작업할 수 있어야 하므로)
  - **예외 한 가지**: 이미 시험 응시 중이던 사용자의 최종 제출(`POST /exams/{id}/solve`)만은 점검 중에도 통과됨 — 답안이 브라우저에만 있다가 서버 저장 안 되고 날아가는 걸 막기 위함
- 사용 시나리오: 배포 중 잠깐 DB 마이그레이션 돌릴 때, 긴급 장애 대응 중일 때

### 점검 모드 켜는 절차
1. 관리자 로그인
2. `/admin/maintenance` 이동
3. 점검 모드 ON, 안내 메시지·예상 종료 시각 입력 후 저장
4. 사용자 화면에서 실제로 점검 화면이 뜨는지 시크릿창으로 확인 (선택이지만 권장)
5. 작업 끝나면 다시 OFF로 저장

---

## 2. 사전 공지 배너 (차단 없음)

- `/admin/maintenance` 화면에서 입력하는 항목
  - 배너 ON/OFF
  - 배너 문구
  - 노출 예정 시각
- 점검 모드와 완전히 독립적으로 동작함 — 배너만 켜도 서비스는 그대로 정상 이용 가능, 화면 상단에 안내 문구만 추가로 보임
- 사용 시나리오: "8/20 새벽 2시~3시 정기점검 예정입니다" 처럼 미리 알려야 할 때

---

## 3. 두 기능 조합 사용 팁

- 일반적인 흐름: **며칠 전부터 배너로 예고 → 실제 점검 시각에 점검 모드 ON → 끝나면 점검 모드 OFF + 배너도 OFF**
- 배너만 켜놓고 점검 모드는 안 켜는 것도 가능 (예: 예고만 하고 실제 점검은 트래픽 적은 새벽에)
- 점검 모드만 켜고 배너는 안 켜는 것도 가능 (예: 예고 없이 긴급 점검 들어가는 경우)

---

## 4. 주의사항

- 점검 모드를 켠 채로 깜빡하고 그대로 두면 서비스 전체가 계속 막혀있는 상태가 되므로, 켤 때 "예상 종료 시각"을 반드시 입력하고 실제로 그 시각에 껐는지 확인하는 습관 들이기
- 관리자 계정 자체가 잠기면(로그인 5회 실패) 점검 모드를 끌 수단이 없어짐 → 점검 작업 시작 전에 관리자 로그인이 잠겨있지 않은지 미리 확인하기
