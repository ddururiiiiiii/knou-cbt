# 아무도 신고하지 않은 버그: 문제 이미지가 저장할 때마다 조용히 사라지던 이야기

## 문제

사용자 신고로 발견한 게 아니었다. 문제 등록 화면을 손보다가 우연히 재현됐다 — 이미지가 첨부된 문제를 열어서, 이미지는 그대로 둔 채 문제 지문의 오탈자만 고치고 저장했더니, **저장 후 다시 열어보면 이미지가 사라져 있었다.**

이미지를 다시 첨부하지 않고 다른 값만 살짝 고쳐서 저장할 때마다 이런 일이 벌어졌다. 재현이 너무 쉬웠는데, 그동안 아무도 신고를 안 했다는 게 오히려 무서웠다. 이미지가 있는 문제를 수정할 일 자체가 드물었거나, 수정한 사람이 "어? 이미지 없네"하고 그냥 다시 올렸을 가능성이 있었다.

## 원인

문제 등록/수정 폼(`questionManage.html`)의 테이블에서, 이미지가 있는 문제는 이미지 아이콘만 툴팁으로 보여줬다.

```html
<td th:if="${q.imageUrl != null}">
    <span ... th:title="|<img src='${q.imageUrl}' .../>|">
        <svg>...</svg>
    </span>
</td>
```

문제는 이 마크업에 `imageUrl` 값을 폼 제출 시 서버로 실어 보내는 **hidden input이 아예 없었다**는 점이다. 파일 입력(`<input type="file">`)은 있었지만, 파일을 새로 선택하지 않으면 그 필드는 빈 채로 제출된다. 결국:

- 이미지 파일을 새로 첨부 → 정상 저장
- 이미지는 그대로 두고 다른 값만 고쳐서 저장 → `imageUrl`을 실어 보내는 필드가 애초에 없으니, 서버는 이 값을 "비어있음"으로 받고 **기존 이미지 URL을 null로 덮어써버림**

거기에 서비스 로직도 한몫했다. `blankToNull()` 처리가 `imageUrl`에는 빠져 있어서, 애매하게 빈 문자열이 들어와도 걸러지지 않고 그대로 저장되는 경우까지 있었다.

```java
// Before
req.getImageUrl(),

// After
blankToNull(req.getImageUrl()),
```

## 해결

두 가지를 같이 고쳤다.

**① 기존 이미지 URL을 유지하는 hidden input 추가**

```html
<input type="hidden" th:name="|questions[${iterStat.index}].imageUrl|"
       th:value="${q.imageUrl}" class="question-image-url-input"/>
```

이제 파일을 새로 첨부하지 않아도, 폼 제출 시 기존 `imageUrl` 값이 항상 같이 실려간다. "재첨부 안 함 = 기존 값 유지"가 되도록 만든 것이다.

**② 삭제와 "재첨부 안 함"을 명확히 구분**

기존엔 재첨부를 안 하면 어차피 사라졌으니 "삭제"라는 개념이 따로 필요 없었다. 하지만 hidden input으로 기존 값을 유지하게 되면, 이번엔 반대로 "일부러 이미지를 지우고 싶을 때" 방법이 없어진다. 그래서 명시적인 삭제 버튼을 별도로 추가해서, 사용자가 의도를 명확히 표현할 수 있게 했다.

## 교훈

- "재첨부하지 않으면 값을 유지한다"는 당연해 보이는 동작이, 실제로는 명시적으로 구현해줘야만 성립하는 동작이다. HTML 폼은 "이 필드는 안 건드렸으니 서버가 알아서 기존 값을 유지해주겠지"라는 가정을 해주지 않는다. 값을 유지하고 싶으면 그 값을 다시 실어 보내야 한다.
- 이런 종류의 데이터 유실 버그는 에러를 던지지 않는다. 저장은 "성공"하고, 화면도 정상적으로 넘어간다. 다만 조용히 값 하나가 사라질 뿐이다. 에러 로그도, 사용자 신고도 없이 이런 버그가 오래 살아남을 수 있다는 걸 이번에 체감했다.
- "값을 지우는 것"과 "값을 그대로 두는 것"은 사용자 의도가 명확히 다른데, 폼 설계가 이 둘을 구분할 수 없는 구조라면 결국 한쪽이 다른 쪽을 삼켜버린다. 편집 폼을 설계할 때는 "아무것도 안 건드렸을 때 뭐가 서버로 가는지"를 항상 확인해야 한다.
