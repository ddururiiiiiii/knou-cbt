# 회원 OAuth 로그인 설계 — 결정 사항 정리

`claude/app-login-implementation-order-69ml8a` 브랜치에서 진행. 로그인/회원가입을 붙여서 회원이 자신의 응시 기록을 확인할 수 있게 하는 기능. 대화로 정리된 결정 사항을 구현 전에 문서로 남겨둔다.

## 목표
- 구글 / 카카오 / 네이버 OAuth 로그인으로 회원가입·로그인 (애플은 제외 — 앱스토어에 올릴 때 필요해지면 그때 추가)
- 로그인한 회원은 자신의 시험 응시 기록(과목/시험/점수/제출일시)을 마이페이지에서 확인 가능
- 비회원 응시는 계속 허용 (로그인 강제하지 않음)

## 주요 결정

| 항목 | 결정 |
|---|---|
| 회원 테이블 | 기존 관리자용 `users` 테이블과 완전히 분리 — 새 `member` 테이블 신설 |
| 유저 식별자 | `provider` + `provider_id` 조합 (이메일은 부가정보로만 저장, PK로 안 씀 — 카카오/네이버는 이메일이 선택 동의라 안 올 수도 있고 나중에 바뀔 수도 있음) |
| 여러 소셜 계정 연동 | 자동 연동 안 함. 구글로 가입 후 카카오로 로그인하면 별개 신규 계정으로 생성. 필요해지면 나중에 수동 연동 기능 추가 |
| 가입 시 수집 정보 | 이메일, 닉네임, 학과(선택, 기존 `department` 재사용) — 학과는 나중에 개인화·통계에 재사용 가능 |
| 비회원 응시 | 계속 허용. `/exams/**`는 로그인 없이도 접근 가능한 상태 유지 |
| 응시 기록 저장 기준 | 기존 `exam_attempt_log`와 동일 — 제출 시점에만 기록, 입장/이탈은 추적 안 함. 로그인 상태면 `user_id` 채움 |
| 같은 시험 재응시 | 매번 새 이력으로 계속 누적 (최신 것만 남기지 않음) |
| 관리자/회원 로그인 | 진입점 완전 분리 — 관리자는 기존 `/admin/login`(ID/PW) 그대로, 회원은 신규 `/login`(소셜 버튼만) |
| 회원 탈퇴 | 완전 삭제 대신 절충 — `member`의 개인식별정보(이메일/닉네임/연동정보)는 삭제하되, `exam_attempt_log.user_id`는 NULL로 되돌려 비식별화. 통계 집계 연속성 유지 + 개인정보보호법 파기 요건 충족 |
| 애플 로그인 | 제외 — 웹만 서비스하는 동안은 불필요, 나중에 iOS 앱을 스토어에 올릴 때(App Store 4.8 규정) 추가 |
| 카카오/네이버 검수 | 닉네임 정도만 받을 예정이라 비즈니스 앱 전환 없이 가능할 것으로 판단 — 실제 등록 시 최신 정책 재확인 필요 |
| 최근 로그인 수단 표시 | 로그인 성공 시 쿠키(`last_login_provider`, 1년 만료)에 provider 저장, `/login` 페이지에서 JS로 읽어 해당 버튼 강조 |
| 배포 방식 | feature flag(`app.member-login.enabled`, env var `MEMBER_LOGIN_ENABLED`)로 네비게이션 노출 여부만 제어. 라우트 자체는 항상 열려있어 특정 경로로 직접 테스트 가능. 마지막에 env var만 켜서 재배포 없이 공개 |

## 관리자 화면
- `/admin/members` — 회원 목록 조회(검색/페이징), 강제 탈퇴(삭제)
- 회원별 응시 이력 상세 조회는 이번 범위에서 제외 (필요해지면 추가)

## 회원 화면
- `/login` — 소셜 로그인 버튼 3개, 최근 로그인 수단 강조
- `/mypage` — 내 정보(닉네임/학과/이메일) + 응시 이력 목록(페이징) + 탈퇴

## DB 변경
- `V10__create_member.sql`: `member` 테이블 신설 (provider, provider_id UNIQUE, email, nickname, department_id, last_login_at, created_at, updated_at)
- `exam_attempt_log.user_id`는 기존 컬럼(V9에서 이미 nullable로 마련해둔 것) 그대로 사용 — 스키마 변경 없이 채워 쓰기만 함

## 통계 대시보드 Phase 2와의 연결
`docs/design/statistics-dashboard.md`에 미리 정리해둔 "로그인 도입 후 확장" 항목(가입자 추이, 사용자별 응시 이력 등)은 `member.created_at`과 `exam_attempt_log.user_id`가 채워지기 시작하면 바로 집계 가능해진다. 이번 작업 범위에는 포함하지 않음 — 필요해지면 이어서 진행.

## 이번 범위에서 의도적으로 미룬 것
- 계정 연동(같은 사람이 여러 소셜로 가입한 경우 병합)
- 관리자용 "회원별 응시 이력 상세 조회" 화면
- 애플 로그인
- DAU/MAU, 리텐션 등 로그인 이벤트 기반 통계
